Build a Next.js 14 (App Router) + TypeScript + Tailwind CSS web app called MINDFRAME —
a noir-themed detective game that teaches critical thinking by having players solve
murder mysteries through spotting cognitive biases and logical fallacies in suspect
statements.

TECH STACK:
- Next.js 14 App Router, TypeScript, Tailwind CSS
- State: zustand with persist middleware (localStorage)
- No backend — all game data lives in typed TypeScript data files

DESIGN TOKENS (use these exactly):
- Background: #0B0F14 (noir dark)
- Card background: #11161D (ink)
- Primary accent: #F5B841 (amber) — used for XP, highlights, headers
- Secondary accent: #4DE1C1 (neon teal) — correct answers
- Error/alert: #E4572E
- Muted text: #8FA3B8
- Font: monospace for UI/headers, uppercase tracking-widest for titles

===========================================
PHASE 1 — BUILD THIS FIRST (core loop)
===========================================

1. Landing page → "Enter the City" button → /city
2. City hub page showing player XP and a grid of districts (Crime Scene unlocked by
   default, others show as locked with a lock icon and a tooltip like "Coming soon")
3. Crime Scene district (/cases) → grid of murder case cards (title, difficulty,
   genre, XP reward, synopsis, suspect/clue counts)
4. Clicking a case opens /cases/[id] — a two-panel investigation screen:
   LEFT/CENTER: "Conspiracy Board" — suspect statements listed in a sidebar, draggable
   onto a center corkboard area. Each dropped statement can be tagged with fallacies
   and biases via an expandable checkbox list. A right panel lists suspects to accuse
   and an "Accuse & Submit" button.
   RIGHT: Sidebar showing case overview (victim bio, synopsis), clues (some marked as
   red herrings), suspects with alibis and statements, and a fallacy/bias reference
   list — all in collapsible sections.
5. On accusation, score the investigation:
   - 60% of case XP for correct suspect
   - 40% scaled by % of ground-truth fallacies/biases correctly tagged (only tags on
     statements that actually contain that fallacy/bias count — no credit for
     over-tagging)
   - Show a results panel: correct/wrong, accuracy %, XP earned, missed
     fallacies/biases with definitions, and the full solution explanation
6. XP and completed case IDs persist in localStorage via zustand. Returning to the
   city hub reflects updated XP.

DATA TO INCLUDE IN PHASE 1:
- 5 full murder cases, each with: id, title, genre, difficulty (1-3), synopsis,
  victim bio, 3 clues (one a red herring), 3 suspects each with an alibi and 2
  statements. Each statement should contain ONE clear fallacy or bias baked into its
  wording (not just labeled — the statement text itself should demonstrate the
  fallacy, e.g. a false-dilemma statement literally presents only two options).
- 8 logical fallacies and 6 cognitive biases as a reference taxonomy (id, name, short
  definition), used for tagging.

PHASE 2 — Bias District
- /district/biases → grid of 30 cognitive bias "buildings" (cards)
- /district/biases/[biasId] → detail page per bias: short definition, full
  definition, a detective-context example, a real-world example, a short interactive
  scenario with 2-3 choices and feedback, and a 3-question quiz
- Completing a bias's quiz marks it complete in the store and awards XP
- Unlocks this district on the city hub once built

PHASE 3 — Fallacy District
- Same pattern as Phase 2, but for 30 logical fallacies instead of biases
- Reuse the same components/layout as the Bias District for consistency

PHASE 4 — Detective Academy
- /academy → list of guided lessons (ordered)
- /academy/[lessonId] → lesson runner: a sequence of dialogue steps (from a
  "Sherlock" or "Chief" character) delivered in a typewriter-style reveal, followed by
  a short quiz
- Completing a lesson awards XP and marks it complete

PHASE 5 — Decision Laboratory
- /lab → list of moral/practical dilemma scenarios
- /lab/[scenarioId] → branching decision runner: a setup, then a series of prompts
  each with 2-3 options; each option shows outcome text and links to a bias it
  relates to; track a running score across the decisions

PHASE 6 — Argument Analyzer
- /analyzer → a text box where the player pastes any argument (e.g. a tweet, a
  speech excerpt)
- Run a simple keyword/pattern heuristic engine that flags likely fallacies in the
  text and highlights the relevant phrases with tooltips explaining the fallacy

PHASE 7 — Mind Palace
- /palace → a personal notebook: player can save notes tied to any bias/fallacy/case
- Implement simple spaced repetition (SM-2 lite): each note has a "next review date"
  and interval that grows when the player marks it "remembered" and shrinks when
  marked "forgot"
- A daily review queue showing notes due today

PHASE 8 — Achievements
- Define ~20 achievements (e.g. "Solve your first case," "Catch every fallacy in a
  case," "7-day streak")
- Show a toast notification (bottom-right, auto-dismiss after 4s) when one unlocks
- /profile page showing all achievements, earned and locked

PHASE 9 — 3D City Scene (build LAST — highest risk)
- Replace the simple 2D city hub with a real 3D scene using @react-three/fiber,
  @react-three/drei, and three
- Procedural low-poly buildings only (boxes/cylinders/cones) — no external 3D models
  or textures, so it always runs without missing-asset errors
- Each district is a cluster of buildings; locked districts appear grayscale with a
  lock icon; unlocked districts are lit up and clickable
- On screens under 768px wide, automatically fall back to the simple 2D grid instead
  of loading the 3D canvas (mobile-safe fallback)

PHASE 10 — Polish Pass
- Add hover animations (scale + lift) to all cards
- Add streak tracking (consecutive days visited) shown on the city hub
- Full keyboard navigation and screen-reader labels on all 2D content
- Sound toggle for subtle UI click sounds (default off, no autoplay)
